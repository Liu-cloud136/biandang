# 「诶呀妈呀 今天吃啥呀」功能探索

> 建立时间：2026-08-04（v0.2.4e 提交审核后）
> 用途：盘点可新增功能，评估收益/成本/风险，作为后续排期的候选池。
> 纪律前提：小程序已上线，微信禁频繁审核。**优先做纯后端改动**（零发版），前端改动攒批次一起发。

---

## 一、现状盘点

### 已有页面（8 个）
| 页面 | 职责 |
|---|---|
| `index` | 主推荐页：多场景 AI 出图文、选菜、收藏、做法、签到、分享、尝鲜 |
| `setup` | 11 步偏好引导 |
| `history` | 已采纳历史列表 |
| `history/detail` | 历史详情 |
| `mine` | 用户中心：偏好/收藏/贡献/反馈/备份/忌口/尝鲜/调校/注销 |
| `favorites` | 收藏列表（本地+云端去重） |
| `tuning` | 推荐调校 9 项软旋钮（本次待审核） |
| `admin` | 管理后台 8 个 tab |

### 已有核心链路
- **出文**：`getRecommendation`（全量/sceneMode，按所选场景数扣次，每场景 1 点，先 baseFree 后 bonusFree）→ `commitRecommendation`（仅入库，不扣次）
- **次数经济**：签到 +2 / 测试期「领次数」直送 25（广告位未开通，正式上线改激励视频）/ 贡献发次 / 管理员发次；`baseFree` + `bonusFree`，永久保留跨天不清零
- **内容沉淀**：收藏、历史、做法指南、菜品图（768x768）
- **UGC**：`submitContribution` → AI 审核 → `mergeContributions` 合并进主库
- **调校**：9 项旋钮注入提示词（explore/tasteShift/health/complexity/repeatGuard/surprise/nutrition/seasonal/serving）

### 明显的能力空白
1. **吃完之后没有闭环** —— 推荐→采纳后就断了，没有"做了没/好不好吃"的回收
2. **没有采购侧** —— 知道吃什么，但不知道要买什么
3. **数据只进不出** —— 历史攒了很多，用户看不到任何汇总洞察（原"使用报告"已删）
4. **单机体验** —— 全是一个人用，没有任何双人/家庭场景
5. **被动等用户打开** —— 无任何触达能力

## 二、候选功能池

按「零发版 → 小改动 → 大工程」排序。每项标注：**收益**（对留存/活跃的帮助）、**成本**、**是否需发版**、**风险**。

---

### A 类：纯后端，零发版（推荐优先做）

#### A1. 提示词能力持续增强
**做什么**：不动任何前端，只在 `getRecommendation` 里加提示词维度。
- 天气联动：云函数取当日天气（或按季节+温度近似），热天倾向凉菜/汤水，冷天倾向炖煮/暖食
- 节气/节日：清明青团、冬至饺子、中秋、端午等，当天推荐里带一道应景的
- 星期效应：工作日晚饭偏快手，周末偏"值得花时间"

**收益**：★★★★ 用户直接感知"它好像懂我"，且零发版
**成本**：低，改一个云函数
**风险**：低。天气 API 若走外部 HTTP 需注意云函数出网与超时，可先用"季节+月份"近似，不引外部依赖

#### A2. 重复度治理升级
**做什么**：现在 `repeatGuard` 只是按天数排除近期已选。可升级为：
- 统计用户历史里出现频次 top N，在提示词里标注"这些已经吃腻了，降低权重"
- 反过来标注"很久没出现过的老朋友"，偶尔唤回

**收益**：★★★ 直接解决"翻来覆去就那几道"的核心抱怨
**成本**：低，读 `recommend_history` 做聚合
**风险**：低

#### A3. 出文质量兜底与降级链路
**做什么**：混元 429 限流时，当前是退避重试。可加：
- 命中限流时先返回一份"从用户历史高分菜里现搭的组合"，标注来源，用户体验不中断
- 后台异步补一次真 AI 出文，下次打开时替换

**收益**：★★★ 高峰期不白等
**成本**：中
**风险**：中，逻辑复杂度上升，需谨慎处理扣次与退款

#### A4. 管理后台数据看板（admin 页已有 tab 机制）
**做什么**：admin 页加一个"数据"tab，看 DAU、出文量、AI 失败率、次数消耗分布、热门菜 top20。
**注意**：admin 页是前端，加 tab 要发版。**但可以先把云函数写好**（`getAdminStats`），等下次发版时前端一起接。

**收益**：★★★ 对你自己运营有用
**成本**：中
**风险**：低

---

### B 类：小前端改动，可攒批次

#### B1. 买菜清单 ⭐ 最推荐
**做什么**：采纳推荐后，一键生成这几道菜的**合并购物清单**（同食材自动合并、按生鲜/肉蛋/调料分区）、可勾选、可复制文本、可分享给家人。

**为什么值得做**：
- 这是当前链路最自然的下一步，"决定吃什么"之后必然是"去买"
- 高频复用：每周买菜都要用，能显著拉高打开率
- 技术上不难：菜品→食材映射 AI 已经能出，或从 `dish_library` 取

**收益**：★★★★★
**成本**：中（一个新页面 + 一个云函数）
**发版**：需要
**风险**：低

#### B2. 做过了 / 打分闭环
**做什么**：历史详情页加一个"做过了"按钮 + 三档评价（好吃/一般/不合胃口）。评价数据反哺推荐：
- 差评的菜进入软降权
- 好评的菜提升同类权重

**收益**：★★★★ 补上唯一的反馈闭环，让推荐真正越用越准
**成本**：中（前端一个按钮 + 云函数写库 + 提示词读取）
**发版**：需要（但改动很小，历史详情页加个按钮）
**风险**：低

#### B3. 冰箱里有什么 → 反向推荐
**做什么**：输入手头现有的几样食材，AI 反推能做什么菜。
**收益**：★★★★ 场景非常真实（下班回家看冰箱），且和现有偏好体系天然结合
**成本**：中（一个入口 + 复用 `getRecommendation` 加 action）
**发版**：需要（可以只在 index 加一个入口，或塞进现有的"尝鲜"位置旁）
**风险**：低

#### B4. 一周菜单规划
**做什么**：一次性生成 7 天菜单，考虑营养均衡与食材复用（周一买的菜周三还能用上）。
**收益**：★★★★ 客单价型功能，一次消耗多次次数，对次数经济友好
**成本**：中高（新页面 + 长提示词 + 出文时间长，需注意 60s 超时）
**发版**：需要
**风险**：中，出文时间是硬约束，可能要拆成分批出

#### B5. 剩菜改造
**做什么**：输入剩下的菜，AI 给二次利用方案（剩米饭→蛋炒饭/粥）。
**收益**：★★★ 有趣，低频但口碑好
**成本**：低（复用现有出文链路加 action）
**发版**：需要一个入口
**风险**：低

---

### C 类：需要较大投入，先观望

#### C1. 家庭/双人模式
**做什么**：多人绑定同一"饭桌"，推荐时同时满足双方偏好与忌口，一起看历史。
**收益**：★★★★ 社交裂变属性强，天然带新
**成本**：高（账号关系、权限、数据隔离、邀请码——注意 `invite_codes`/`user_invites` 集合之前已删除，要重建）
**发版**：需要
**风险**：中高，涉及数据模型改动和权限设计

#### C2. 订阅消息触达
**做什么**：饭点前推送"今天吃这个？"（需用户主动订阅）。
**收益**：★★★★ 唯一的主动触达手段，对留存影响最大
**成本**：中（订阅消息模板申请 + 定时云函数 + 前端授权弹窗）
**发版**：需要
**风险**：中，微信对订阅消息管控严格，滥用会被封能力；一次性订阅 vs 长期订阅要选对

#### C3. 菜谱视频/步骤图
**收益**：★★ 有做法文本已够用，边际收益低
**成本**：高（内容源、版权）
**结论**：不建议

#### C4. 社区/晒图
**收益**：★★ 需要冷启动用户量，现阶段没有
**风险**：UGC 图片内容审核成本高，合规风险大
**结论**：暂不考虑

## 三、优先级建议

### 第一梯队（现在就能做，零发版）
1. **A1 节气/天气/星期提示词增强** —— 立刻有感知，零风险
2. **A2 重复度治理升级** —— 解决核心抱怨
3. **A4 的云函数部分** —— 提前写好等下次发版

### 第二梯队（攒进下一个发版包）
4. **B1 买菜清单** —— 最高价值的新功能
5. **B2 做过了/打分** —— 补上反馈闭环，改动小
6. **B3 冰箱反推** —— 场景真实，可复用现有链路

### 第三梯队（想清楚再动）
7. **C2 订阅消息** —— 留存杀手锏，但要先想好推送节奏与文案，别惹烦用户
8. **B4 一周菜单** —— 要先解决出文超时
9. **C1 家庭模式** —— 数据模型改动大，等用户量起来再说

---

## 四、决策问题（需要你拍板）

1. **B1 买菜清单**是不是你也觉得最值得做？如果是，下次发版包就以它为主体。
2. **A 类零发版的三项**要不要现在就开工？完全不影响审核中的版本。
3. **C2 订阅消息**你愿不愿意做？它是留存提升最大的一项，但需要你决定推送时间点和频次（建议：仅用户主动点"提醒我"才订阅，每次一条，不做批量群发）。
4. **广告申请**进展如何？如果流量主开通，次数经济会宽松很多，B4 一周菜单这种"一次消耗多次"的功能才有空间。

## 五、明确不做的

- 深色模式 / 字号调节（全局工程，触发大发版，用户已明确去掉）
- 后端下发 UI 结构（uiSchema 那套，2026-08-04 已评估否决：页面异构、审核风险、引擎维护成本 > 收益）
- 菜谱视频、社区晒图（成本高、合规风险大、无冷启动用户）
- 狗肉/蛇肉/猫肉相关内容（永久不收录）
